INSTALABEL BACKEND PAGINATION IMPLEMENTATION GUIDE
====================================================

OVERVIEW
--------
This guide shows how to implement backend pagination for the /api/logs endpoint
to support the frontend pagination changes already made.

FRONTEND CHANGES MADE
---------------------
The frontend now sends these query parameters:
- page: Page number (starts at 1)
- limit: Number of logs per page (default 20)
- dateFrom: Only logs from this date onwards (YYYY-MM-DD format)
- action: Filter by action type (e.g., "print_label")

Example API calls being made:
GET /api/logs?page=1&limit=20&dateFrom=2024-08-04&action=print_label
GET /api/logs?page=2&limit=20&dateFrom=2024-08-04&action=print_label

BACKEND IMPLEMENTATION
----------------------

1. UPDATE YOUR LOGS API ENDPOINT
--------------------------------
Replace your current /api/logs endpoint with this implementation:

```javascript
app.get('/api/logs', authenticateToken, async (req, res) => {
  try {
    const { page = 1, limit = 20, dateFrom, action } = req.query;
    const userId = req.user.id; // Assuming you have user from auth middleware
    
    // Validate parameters
    const pageNum = Math.max(1, parseInt(page) || 1);
    const limitNum = Math.min(100, Math.max(1, parseInt(limit) || 20)); // Max 100 items per page
    
    // Build database query conditions
    const conditions = { user_id: userId };
    
    // Add date filter if provided
    if (dateFrom) {
      const startDate = new Date(dateFrom);
      startDate.setHours(0, 0, 0, 0); // Start of day
      conditions.created_at = { $gte: startDate };
    }
    
    // Add action filter if provided
    if (action) {
      conditions.action = action;
    }
    
    // Calculate pagination
    const skip = (pageNum - 1) * limitNum;
    
    // Execute query with pagination
    const logs = await Log.find(conditions)
      .sort({ created_at: -1 }) // Most recent first
      .skip(skip)
      .limit(limitNum)
      .lean(); // Use lean() for better performance
    
    // Get total count for pagination metadata
    const totalCount = await Log.countDocuments(conditions);
    const totalPages = Math.ceil(totalCount / limitNum);
    
    // Response format
    res.json({
      logs,
      pagination: {
        currentPage: pageNum,
        totalPages,
        totalCount,
        hasMore: pageNum < totalPages,
        limit: limitNum
      }
    });
    
  } catch (error) {
    console.error('Error fetching logs:', error);
    res.status(500).json({ 
      error: 'Failed to fetch logs',
      message: error.message 
    });
  }
});
```

2. ADD DATABASE INDEXES (CRITICAL FOR PERFORMANCE)
--------------------------------------------------
Add these indexes to your logs collection/table:

MongoDB:
```javascript
db.logs.createIndex({ user_id: 1, created_at: -1 });
db.logs.createIndex({ user_id: 1, action: 1, created_at: -1 });
```

PostgreSQL:
```sql
CREATE INDEX idx_logs_user_created ON logs(user_id, created_at DESC);
CREATE INDEX idx_logs_user_action_created ON logs(user_id, action, created_at DESC);
```

3. ADD VALIDATION MIDDLEWARE (OPTIONAL BUT RECOMMENDED)
-------------------------------------------------------
```javascript
const validatePaginationParams = (req, res, next) => {
  const { page, limit } = req.query;
  
  if (page && (isNaN(page) || parseInt(page) < 1)) {
    return res.status(400).json({ error: 'Invalid page parameter' });
  }
  
  if (limit && (isNaN(limit) || parseInt(limit) < 1 || parseInt(limit) > 100)) {
    return res.status(400).json({ error: 'Invalid limit parameter (1-100)' });
  }
  
  if (req.query.dateFrom && isNaN(Date.parse(req.query.dateFrom))) {
    return res.status(400).json({ error: 'Invalid dateFrom format (YYYY-MM-DD)' });
  }
  
  next();
};

// Use it in your route:
app.get('/api/logs', authenticateToken, validatePaginationParams, async (req, res) => {
  // ... your handler
});
```

6. PERFORMANCE OPTIMIZATIONS (OPTIONAL)
---------------------------------------
Add Redis caching for better performance:

```javascript
const redis = require('redis');
const client = redis.createClient();

app.get('/api/logs', authenticateToken, async (req, res) => {
  try {
    const { page = 1, limit = 20, dateFrom, action } = req.query;
    const userId = req.user.id;
    
    // Create cache key
    const cacheKey = `logs:${userId}:${page}:${limit}:${dateFrom || 'all'}:${action || 'all'}`;
    
    // Try to get from cache first
    const cached = await client.get(cacheKey);
    if (cached) {
      return res.json(JSON.parse(cached));
    }
    
    // ... your database query logic ...
    
    const result = {
      logs,
      pagination: {
        currentPage: pageNum,
        totalPages,
        totalCount,
        hasMore: pageNum < totalPages,
        limit: limitNum
      }
    };
    
    // Cache for 5 minutes
    await client.setex(cacheKey, 300, JSON.stringify(result));
    
    res.json(result);
  } catch (error) {
    // ... error handling
  }
});
```

8. TROUBLESHOOTING
------------------
Common issues and solutions:

Issue: Slow queries
Solution: Add database indexes (step 2)

Issue: Invalid date format errors
Solution: Add validation middleware (step 3)

Issue: Memory issues with large datasets
Solution: Use lean() queries and proper pagination

Issue: Frontend not receiving expected data
Solution: Ensure response format matches step 4 exactly
